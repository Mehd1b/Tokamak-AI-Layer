## Time-Weighted Accumulators

| Accumulator | Formula | Controllable Input | Time Source | Unbounded? | Exposure |
|---|---|---|---|---|---|
| Management fee shares | `feeShares = totalShares * managementFeeBps * timeElapsed / (365 days * 10000)` | `timeElapsed = block.timestamp - lastFeeTimestamp` | block.timestamp | Bounded by managementFeeBps <= 500 | ACCUMULATION EXPOSURE: if `lastFeeTimestamp` is not updated for a long period (e.g., vault is idle with no deposits/executions), timeElapsed grows unboundedly. On next collect, fee = totalShares * 5% * years. This is intentional for management fee, but if owner deliberately avoids calling collect while TVL rises, depositors face a lump-sum fee. The `FEE_CHANGE_COOLDOWN` guards against rapid cycling but not slow accumulation. |
| Performance fee shares | `profitBps = (currentPps - hwm) * 10000 / hwm; feeShares = totalShares * profitBps * perfFeeBps / (10000^2)` | PPS depends on totalAssets (which changes via execute) and totalShares (which changes via deposits/fee mints) | N/A (event-driven) | Bounded by MAX_PERFORMANCE_FEE_BPS=5000 and HWM advance | PPS can be manipulated by artificially inflating totalAssets (e.g., an agent returning more than deployed → large profit). Fee is bounded by the actual PPS gain above HWM. |
| PointsProgram accrual | `rawPoints = (normalized * elapsed * multiplier) / (1e18 * 86400)` | `elapsed = _accrualNow() - lastAccrualTimestamp`; `multiplier` depends on `block.timestamp <= deployedAt + 30 days` | block.timestamp (clamped to seasonEnd) | Bounded by seasonEnd if set; otherwise unbounded | ACCUMULATION EXPOSURE: if `accruePoints` is not called for a long time, a large `elapsed` multiplies by depositBalance in one call. Formula uses `(normalized * elapsed * multiplier)`: if normalized = 1e30, elapsed = 2 years = 63M seconds, multiplier = 3, product = 1.89e38 before division by 1.73e23 = 1.09e15 points. No overflow for realistic values but can be very large. |
| Oracle attestation age check | `block.timestamp - oracleTimestamp <= maxOracleAge` | `oracleTimestamp` (caller-supplied) | block.timestamp | Bounded by maxOracleAge | No accumulation; spot check only. |
| Bond expiry | `block.timestamp >= bond.lockedAt + BOND_EXPIRY (90 days)` | `bond.lockedAt` set at lock time | block.timestamp | N/A | Fixed duration; no accumulation risk. |

### SYNC_GAP flags
- `sync_gaps = 5` (totalShares/snapshotTotalShares during fee minting, snapshotTotalAssets/snapshotTotalShares in emergency clamp, totalDeposited/totalWithdrawn cross-path, depositPoints/totalPoints multi-writer, trackedIdle/balanceOf in sweep)

- `conditional_writes = 12` (strategyActive conditional set, snapshotTotalAssets conditional set, trackedETHBalance isETH conditional, highWaterMark conditional reset, lastFeeTimestamp conditional reset, _resetFeeEpochIfEmpty conditional, fee guard during strategyActive, slashPending conditional clear, snapshotTotalShares clamp in emergency, _depositToVault clamp, multiplier time-dependency, _pendingCount dec-on-revert)

### ASYMMETRIC_BRANCH flags
- `asymmetric_branches = 2` (snapshotTotalAssets vs snapshotTotalShares independent clamps in emergency, trackedETHBalance decremented in _executeTransferERC20 unconditionally but in _executeCall only when value>0)

- `cluster_gaps = 3` (Fee State cluster: HWM and lastFeeTimestamp reset together in _resetFeeEpochIfEmpty but updated independently elsewhere; Strategy Snapshot: strategyActivatedAt cleared in _settle and emergency drain but NOT decremented in _processWithdraw; Optimistic Pending: _pendingCount cannot be corrected if decrement path reverts)
